## 2. 浏览器 E2E 发现并修复的真实缺陷

1. **NPC 武器元数据在重载后丢失**
   - 现象：F-3 浏览器用 NPC 持剑攻击，伤害类型仍按徒手钝击结算。
   - 根因：战斗运行时 `participant.id` 是 NPC 卡 id，但 DB `CombatParticipant.id` 是独立 cuid；`loadNpcWeaponsByParticipant` 用 `id in [participant.id]` 查询永远查不到。
   - 修复：创建战斗时把 `__participantId` 写入 `npcData`；读取时按 `__participantId` 反查并过滤（`setup.ts` / `options.ts`）。

2. **服务端 `combat:action` 丢弃战技类型**
   - 现象：浏览器点“使用战技”后日志报“缺少战技类型”。
   - 根因：socket 构造 `ActionSubmission` 时没有复制 `maneuver` 字段。
   - 修复：在 `apps/web/src/server/socket/combat.ts` 中白名单复制 `DISARM/TRIP/GRAPPLE`。

3. **导入角色的专精复合技能在编辑保存时被拒绝**
   - 现象：完整浏览器套件里的 `character-lifecycle.spec.ts` 在保存导入角色时报“存在不属于当前规则包的技能：LANGUAGE_OTHER#拉丁语”，页面停在编辑页。
   - 根因：编辑校验只按 `skillBases[skillId]` 查表，没有把 `BASE#专精` 拆成基础技能 id 再校验。
   - 修复：`draft.ts` 中对 `occupationAdded / interestAdded` 的 key 先取 `#` 前基础 id 再校验，专精数据可正常保存。

4. **医疗结果没有写回战斗席位**
   - 现象：KP 工作台对受伤角色执行自然恢复，面板提示恢复 2 HP，但战斗页 HP 不变。
   - 根因：`persistMedicalOutcome` 把战斗席位同步放在 `combatUpdate !== undefined` 分支里，而调用方没有传 `combatUpdate`。
   - 修复：医疗结果无条件同步到房间内进行中战斗的 participant（HP / 濒死 / 昏迷 / 重伤 / conditions）。

5. **服务端 draft 丢失新角色的专精复合 key**
   - 现象：手工建卡页添加并分配 `LANGUAGE_OTHER#拉丁语` 后提交，DB 中该技能消失。
   - 根因：`draft.ts` 的手工分支只遍历 `compiled.skills` 重建 `skills`，复合 key 只参与校验、没有写回。
   - 修复：按基础技能求值 + 职业点 / 兴趣点重建复合 key 总值并写回 `skills`。

6. **幸运检定前后端参数契约不一致**
   - 现象：KP 工作台点“投幸运检定”后只显示“参数不合法”。
   - 根因：面板发送 `unitRef`，服务端却强制要求 `characterId`。
   - 修复：服务端从 `unitRef` 解析玩家角色 id，NPC / 非法引用直接拒绝。

这些缺陷都是浏览器点击流程实际触发后才暴露，纯规则测试与 `verify:*` 脚本没有覆盖到。

## 3. 真实开一把游戏验证（完整双玩家流程）

测试文件：`apps/web/e2e/coc7-full-game.spec.ts`

这条用例不使用预置战斗快照，也不直接调用服务器函数代替页面操作，而是两个独立浏览器上下文、真实注册两个用户，完整走一遍实际跑团流程：

1. A 用户通过 `/register` 真实注册并自动登录；
2. B 用户通过 `/register` 真实注册并自动登录；
3. A 通过首页表单真实创建 COC7 房间；
4. A 在准备页读出邀请码，B 通过首页“加入房间”表单输入邀请码真实入房；
5. A、B 各自在 `/characters/import` 上传 xlsx 人物卡，走真实导入；
6. A、B 各自在准备页“从我的角色库选择已有角色 → 带入已有角色”；
7. A 作为 KP 在准备页点击“通过”真实审核两张角色；
8. A 在 `/rooms/[id]/scenes` 点“创建场景”，并在准备页 SceneBoard 中真实放置两个角色 Token；
9. A、B 各自点击“我准备好了”；
10. A 在准备页点击“应用团本预设到房间”（如默认选中团本），再点击“开始跑团”；
11. A 在房间页悬停 B 的 Token，真实点击“直接开战”，在发起战斗页选择双方并点击“直接开战”；
12. A、B 分别用各自浏览器进入同一场战斗；
13. 通过战斗页顶部真实的“KP 数值调整”面板把 B 的 HP 调到 200（用于让连射能完整结算）；
14. 真实双人回合：
    - A 浏览器点“攻击”，B 浏览器收到应对面板后选“闪避”并提交；
    - B 浏览器点“攻击”，A 浏览器收到应对面板后选“不应对”并提交；
    - A 浏览器选择“战技：踢倒”并点“使用战技”，B 浏览器选“不应对”；
    - B 浏览器点“跳过”；
    - A 浏览器选择手枪、射击次数 3、点“攻击”，B 浏览器选“不应对”，页面出现第 3/3 发日志。

该用例验证了：真实注册/建房/邀请码加入/角色导入（并断言导入后生成 `LANGUAGE_OTHER#拉丁语` 复合 skill key，覆盖 C-3 后端路径；同时断言武器“长剑”的 skillId 推断为 `格斗（剑）`，覆盖 C-2 剑专精推断）/过审/Token 放置/准备/开始/发起战斗/双玩家真实应对/战技/三连射，全流程均为真实页面操作。

## 4. 本轮新增并已浏览器验证：KP 工作台与补验项

### 4.1 C-3/D-5 手工建卡专精 UI

- 页面：`/rooms/[id]/characters/new`（manual 建卡）。
- 真实操作：填写属性 → 确认年龄补正 → 在“添加专精”选“外语”、填“拉丁语”并添加 → 在合成的“外语（拉丁语）”行填兴趣点 40 → 下一步 → 提交审核。
- DB 断言：`character.skills["LANGUAGE_OTHER#拉丁语"] === 41`（基础 1 + 兴趣 40）。

### 4.2 D-4 医疗与恢复（真实房间动作）

- 页面：战斗页 KP 工作台“医疗与恢复”。
- 真实操作：急救（真实掷骰，面板显示成功/失败结果）；自然恢复（恢复 2 天）。
- 断言：自然恢复后面板 `HP 189 → 191`；数据同时写入 `GameCharacter.currentHp` 与战斗 participant。
- 已接入规则：急救 / 医学 / 自然恢复 / 重伤周检（`packages/rules/src/medical.ts`）。

### 4.3 D-2 环境与持续伤害（KP 操作）

- 页面：KP 工作台“环境 / 持续伤害”。
- 真实操作：对玩家角色施加“火焰 1d6”环境伤害；状态编辑器添加 `POISON`（ROUND 3）再移除。
- 断言：HP 真实下降，面板出现【环境伤害·火焰】；状态列表随添加 / 移除实时变化。
- 说明：持续伤害写成 `DOT` 状态（含表达式与轮数），引擎在回合结束时自动结算并扣减轮数（`resolveRoundEndDotDamage`，接入 `resolvePending` / `endTurn`），浏览器用例 17 已验证。

### 4.4 D-3 幻觉 / 现实检定 / 恐惧症与躁狂症背景写入

- 页面：跑团页 SANITY 模式“疯狂发作 1D10”“现实检定”。
- 真实操作：把 SAN 压到 0 后点“现实检定”（必然失败）；反复真实点击 1D10 直到表 9/10。
- 断言：`conditions` 写入 `HALLUCINATION`；`character.backstory.phobias` 写入新恐惧症/躁狂症；聊天出现“已写入角色背景”。

### 4.5 P3 KP 快捷工具

- 幸运检定：真实点击并显示结果，支持消耗幸运。
- 孤注一掷：填写技能 `DODGE` 与理由后真实重掷，面板显示【孤注一掷】结果。
- 治疗计算器：随输入实时估算急救 / 医学 / 自然恢复 / 重伤周检。

### 4.6 U-3 多目标 / 多技能 routine

- 页面：战斗页“多目标 / 多技能攻击 routine”面板。
- 真实操作：添加两步（徒手 → 防御者1，手枪 → 防御者2），点击“执行多目标 routine”，两个目标分别真实提交“不应对”。
- 断言：同一行动日志中出现两条不同技能 `ATTACK`，两个目标 HP 都下降。

### 4.7 U-6 战斗距离展示与追逐地图距离

- 普通攻击：35 英尺 / 70 英尺面板常驻显示实际距离（浏览器用例 7）。
- 追逐攻击：追逐面板显示“最近敌人地图距离 70 英尺”；真实前进 1 格后攻击同地点目标，服务端把霰弹枪近距 4d6 覆盖为远距 2d6（浏览器用例 18）。

### 4.8 D-1 武器 / 伤害表

- 页面：KP 工作台“武器 / 伤害表”。
- 内容：全部内置武器的技能 / 伤害 / 类型 / 射程 / 距离档 / 射击数，以及重伤 / 濒死 / 极限贯穿 / 火器掩体 / 投掷射程 / 自然恢复规则参考。

### 4.9 D-3 时间推进联动

- 页面：KP 工作台“状态编辑器”内的“推进叙事时间”。
- 真实操作：添加 `HALLUCINATION`（HOUR 1），推进 1 小时。
- 断言：状态自动到期移除，面板出现“已到期”日志。

### 4.10 D-5 专精候选 / D-7 后台内容编辑器 / G-2 成长规则展示

- D-5：KP 工作台维护房间级专精候选，建卡页作为下拉候选（浏览器用例 20）。
- D-7：管理后台规则包版本编辑器新增“技能表”，可逐行编辑 / 增删并与 JSON 共用同一配置，保存为可发布草稿版本（浏览器用例 21）。
- G-2：成长面板常驻显示房间实际生效的 96–100 成长规则（浏览器用例 16）。

以上由 `coc7-full-game.spec.ts` 的真实双人流程与 `coc7-compliance.spec.ts` 的真实页面流程覆盖；全量 Playwright：**24 passed**。
