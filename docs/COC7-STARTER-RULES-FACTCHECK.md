### 最需要优先处理的“违背”类问题

- **1.11 MP 耗尽后，后续应消耗的 MP 直接从 HP 扣除（形式由 KP 决定）。**：战斗外施法直接返回“MP 不足”；战斗内 `resolveMagic` 只把 MP 钳到 0（`actor.mp = Math.max(0, actor.mp - mpCost)`），既不拒绝也不扣 HP。战斗道具/符卡会检查 MP，规则不一致。
- **1.15 在八项职业技能与信用评级上分配：一项70%、两项60%、三项50%、三项40%，直接设值并忽略人物卡基础值。**：系统使用完整版职业点公式（按职业，如 EDU×4、EDU×2+APP×2）与基础值+加点模型，且技能有 80/70 车卡上限；本书是“忽略基础值、直接设九项固定值”的入门模型，两者不是同一分配方式。可直接验证的冲突：书中的记者苏珊把信用评级设为 40，而 `apps/web/prisma/data/occupations.json` 中记者（code 220）的 creditMin=9、creditMax=30，`validateCharacterDraft` 会因“信用评级必须在 9~30 之间”拒绝该示例。
- **1.16 创建角色时不能为克苏鲁神话技能分配点数（除非 KP 同意）。**：已用临时脚本验证：`validateCharacterDraft` 接受 `interest:{CTHULHU_MYTHOS:30}`，返回 ok=true、CTHULHU_MYTHOS=30、maxSan=69。COC7 没有“需 KP 确认”的门槛；库内建卡无 KP 参与。
- **1.17 个人兴趣技能：选择四项非职业技能，在其基础值上各 +20%。**：系统用 `interestPoints = int*2` 的兴趣点池，兴趣上限默认 70，且点数仍按“基础+加点”计算。低 INT 无法为四项各 +20；基础 60 的技能 +20 = 80 会被 70 上限拒绝，无法复现本书模型。
- **1.26 其他语言：角色可学任意数量语言，但每门必须单独支付技能点。**：所有“外语/其他语言（X）”在导入时被 `SKILL_ALIASES['外语']=LANGUAGE_OTHER` 归并到同一技能 id，且 `skills[skillId]=max(旧值,新值)`，多门语言无法并存，只会保留数值最高的一门。
- **1.29 格斗专精包括斗殴、剑、斧、矛、鞭子；射击专精包括手枪、步枪/霰弹枪、弓、弩。**：技能 id 大多存在；但武器到技能的推断只对名称含“斧”的武器使用 `FIGHTING_AXE`，其余近战（含剑）默认 `FIGHTING_BRAWL`，反击 UI 也只允许 `FIGHTING_BRAWL`。弩没有独立技能 id，且 xlsx 的“射击（弩）/射击（弓/弩）”会因模糊匹配落到 `FIREARMS_HANDGUN`（射击（手枪）），而不是 `FIREARMS_BOW`。
- **2.6 成长标记只应给真正成功的检定。**：`dice:skill-check` 用 `isSuccess(check.result)` 判断，常规成功也会自动写入成长池。若 KP 要求的是困难/极难且玩家只掷出常规成功，系统仍会标记为成功成长，KP 必须事后取消。
- **4.5 徒手、小刀与棍棒用格斗（斗殴）；使用剑需要格斗（剑）专精。**：手动武器卡/武器类型 `BLADE` 被推断为 `FIGHTING_BRAWL`；只有 xlsx 导入显式写了“剑”才会映射到 `格斗（剑）`。战斗中反击 UI 也只允许 `FIGHTING_BRAWL`，持剑角色无法按剑专精反击。
- **4.8 闪避：使用闪避技能；攻击者成功等级必须高于闪避者，否则闪避成功；同级时闪避成功。**：`resolveAttack` 中闪避只判断 `isSuccess(dodgeCheck.result)`，随后 `GRAZE_RESOLVE` 在成功时直接归零伤害；完全没有比较攻击者成功等级。结果是常规闪避也能完全躲开极难成功攻击。
- **4.9 反击：使用格斗技能；反击者成功等级需高于攻击者；同级时攻击者获胜。**：引擎直接套用通用 `resolveOpposed`：先比成功等级，等级相同再比目标值（技能值）。因此当双方同为常规/困难成功时，如果防守方反击技能更高，系统会判防守方反击成功；而本书战斗规则明确要求“同级时最初发起攻击的人获胜”，防守方必须达到更高成功等级。
- **4.11 反击成功的一方免于受伤，并能对其对手造成伤害（反击伤害至多按常规成功计算）。**：当前引擎在反击成功时只把本次伤害归零，不向攻击者结算任何反击伤害；HANDOFF 第 37 节也注明“完整反击命中和反击伤害可后续扩展”。因此成功反击不会掉攻击者的 HP。
- **4.12 极限伤害：极难成功时，钝击武器造成最大伤害+DB；贯穿武器造成最大伤害+DB，并额外掷一次武器伤害骰。**：`resolveAttack` 即使攻击掷出 EXTREME/CRITICAL，仍按正常伤害表达式 `rollDice(...)` 结算，没有取最大、附加 DB 或额外伤害骰；攻击等级只写进日志。
- **4.18 子弹无法被闪避；目标只能尝试寻找掩体：闪避成功使攻击者本次射击带惩罚骰，掩体者放弃下一次攻击（若已攻击过则放弃下一轮）。**：引擎对火器仍提供 DODGE，且成功闪避直接免伤；没有“寻找掩体 / 下一击惩罚骰 / 放弃下次攻击”机制。当前实测结果是火器比规则书更容易被完全躲开。
- **4.23 霰弹枪近距离 4D6、否则 2D6，且霰弹枪不能贯穿。**：`weaponDamageOf` 对 `4D6/2D6/1D6` 这种多档伤害永远取第一个可解析档位（即 4D6），战斗又没有距离判定；贯穿规则整体未实现，因此无论距离与成功等级都不会按表变化。
- **7.3 成长掷出 96–100 时必成长（完整版 7e 条款）。**：本书原文只要求“掷出数值高于技能值”；`isGrowthCheckPassed` 额外实现 `roll >= 96`（见 `packages/rules/src/growth.ts:26`），高技能角色可能在按本书应失败时仍然 +1D10。

### 2 游戏系统

| 编号 | 规则书条目 | 结论 | 实现情况 / 证据 |
|---|---|---|---|
| 2.1 | KP 在戏剧性场景要求技能检定；成功即达成目的，失败另有后果。 | **原生** | `dice:skill-check` 自动以 1d100 对角色技能值判定，并输出成功/失败与成长标记。 |
| 2.2 | 成功使用技能后在人物卡上做标记；每项技能同时只能有一个标记。 | **原生** | 成功时自动写入 `GrowthCheck`，`@@unique([gameId, characterId, skillId])`；KP 也可在成长面板手工标记其他技能。 |
| 2.3 | 没有对应技能时，选择最合适的属性当技能检定。 | **KP行为** | 系统没有属性检定动作；KP/玩家可用自由掷骰 `1d100` 与属性值人工比较。 |
| 2.4 | 难度：常规 ≤ 技能值；困难 ≤ 半值；极难 ≤ 五分之一。 | **原生** | `resolveCheck` 按 `criticalAt=1`、`extremeDivisor=5`、`hardDivisor=2` 算出 CRITICAL/EXTREME/HARD/REGULAR/FAIL/FUMBLE；技能页也显示困难/极限值。 |
| 2.5 | KP 在发起检定时应告知难度，并按该难度判定成功。 | **KP行为** | `dice:skill-check` 没有难度参数，但仍会输出 HARD/EXTREME/REGULAR 等级，KP 可据此人工判定；自动成功文案和成长标记不区分难度（见 2.6）。 |
| 2.6 | 成长标记只应给真正成功的检定。 | **违背** | `dice:skill-check` 用 `isSuccess(check.result)` 判断，常规成功也会自动写入成长池。若 KP 要求的是困难/极难且玩家只掷出常规成功，系统仍会标记为成功成长，KP 必须事后取消。 |
| 2.7 | 孤注一掷：检定失败且行动理由充分时可第二次掷骰；再失败将遭遇严重后果，KP 可预先铺垫。 | **KP行为** | 没有孤注一掷流程、失败后果或次数记录；KP 可让玩家改用自由掷骰再掷并口述后果。 |
| 2.8 | 对抗检定：双方各检定，比较成功等级；常规胜失败、困难胜常规、极难胜困难；同级比技能值；同技能值再掷 D100 低者胜。 | **KP行为** | 通用场景没有对抗检定 UI，双方自由掷骰后可人工比较。战斗反击虽使用 `resolveOpposed`，但战斗章有专门规则（同级=攻击者胜，见 4.9），不能直接套用通用同级比技能值逻辑。 |
| 2.9 | 奖励骰/惩罚骰：额外掷一枚十位骰，奖励取较低十位、惩罚取较高十位；可替代或叠加难度，通常用于对抗；奖励与惩罚互相抵消。 | **KP行为** | `resolveCheck` 没有修正值/额外骰接口，UI 也没有奖励/惩罚骰选项。KP 只能放弃自动技能检定，改用自由掷骰并人工解释十位骰。 |
| 2.10 | 奖励/惩罚骰应用于战斗中的自动检定。 | **不可达** | 战斗攻击、闪避、反击由引擎自动掷骰和结算，没有注入额外十位骰的接口，也没有距离/环境/状态自动触发修正。系统内无法自动执行该规则。 |
| 2.11 | 幸运检定：当外部环境或命运决定时，掷 D100 ≤ 当前幸运。 | **KP行为** | 没有幸运检定按钮；幸运是九维之一，KP/玩家可用自由掷骰 `1d100` 与幸运比较。 |
| 2.12 | 群体幸运检定由该场景内幸运最低的调查员代表全队。 | **KP行为** | 系统不会自动找最低幸运；KP 需人工指定玩家或代掷。 |
| 2.13 | 若技能或属性更适合当前状况，应使用它们而非幸运。 | **KP行为** | 检定由 KP 决定；平台提供技能检定与自由掷骰两种入口。 |

### 3 理智

| 3.7 | 陷入疯狂后可能产生幻觉；进行现实检定（视作理智检定）成功可看穿，失败被拖入更深疯狂。 | **KP行为** | 没有幻觉/现实检定状态或自动化；KP 只能自由掷骰并叙事。 |

### 4 战斗

| 编号 | 规则书条目 | 结论 | 实现情况 / 证据 |
|---|---|---|---|
| 4.1 | 战斗时所有调查员、NPC 与怪物依照 DEX 从高到低行动。 | **原生** | COC7 基线 `combat.mode='INITIATIVE'`，`buildInitiativeOrder` 按 DEX 降序；房间也可被房主改成 ATB（本规则书之外）。 |
| 4.2 | DEX 相同时由 KP 决定行动顺序。 | **缺失** | `buildInitiativeOrder` 在平手时按参与者 id 稳定排序；配置虽有 `kpAdjustsOrder=true` 与 `setInitiativeOrder`，但没有 socket/UI 入口，KP 实际无法调整。 |
| 4.3 | 一个战斗轮足够每人完成一次重要行动；轮到角色时 KP 询问其行动。 | **原生** | INITIATIVE 模式每轮每名存活参与者提交并结算一次行动，然后交棒。 |
| 4.4 | 调查员三种战斗技能：格斗、闪避、射击；专精在创建时决定。 | **原生** | 基线技能表包含三类及多种战斗专精；车卡技能区可选。 |
| 4.5 | 徒手、小刀与棍棒用格斗（斗殴）；使用剑需要格斗（剑）专精。 | **违背** | 手动武器卡/武器类型 `BLADE` 被推断为 `FIGHTING_BRAWL`；只有 xlsx 导入显式写了“剑”才会映射到 `格斗（剑）`。战斗中反击 UI 也只允许 `FIGHTING_BRAWL`，持剑角色无法按剑专精反击。 |
| 4.6 | 战斗技能不能孤注一掷；当轮失败后可于下一轮继续攻击。 | **原生** | 系统没有任何孤注一掷入口，战斗检定自然不会孤注；回合结束后下一轮可再次行动。 |
| 4.7 | 近战攻击：轮到角色行动时攻击目标；被攻击者选择闪避或反击；双方掷 D100 比较成功等级。 | **原生** | 攻击检定 + 应对窗口（PASS/DODGE/COUNTER）已实现；近战攻击会下发反击选项，远程不会。 |
| 4.8 | 闪避：使用闪避技能；攻击者成功等级必须高于闪避者，否则闪避成功；同级时闪避成功。 | **违背** | `resolveAttack` 中闪避只判断 `isSuccess(dodgeCheck.result)`，随后 `GRAZE_RESOLVE` 在成功时直接归零伤害；完全没有比较攻击者成功等级。结果是常规闪避也能完全躲开极难成功攻击。 |
| 4.9 | 反击：使用格斗技能；反击者成功等级需高于攻击者；同级时攻击者获胜。 | **违背** | 引擎直接套用通用 `resolveOpposed`：先比成功等级，等级相同再比目标值（技能值）。因此当双方同为常规/困难成功时，如果防守方反击技能更高，系统会判防守方反击成功；而本书战斗规则明确要求“同级时最初发起攻击的人获胜”，防守方必须达到更高成功等级。 |
| 4.10 | 通用对抗检定：若双方成功等级相同且技能值也相同，应再掷 D100，结果较低者获胜。（战斗反击另有“同级攻击者胜”的专门规则，见 4.9。） | **KP行为** | 通用对抗检定没有自动流程，只能双方自由掷骰后人工比较；同值重掷也只能人工执行。系统没有把这条通用规则做成自动对抗检定，因此不构成本条自动违背；但注意不能把它误套到战斗反击上。 |
| 4.11 | 反击成功的一方免于受伤，并能对其对手造成伤害（反击伤害至多按常规成功计算）。 | **违背** | 当前引擎在反击成功时只把本次伤害归零，不向攻击者结算任何反击伤害；HANDOFF 第 37 节也注明“完整反击命中和反击伤害可后续扩展”。因此成功反击不会掉攻击者的 HP。 |
| 4.12 | 极限伤害：极难成功时，钝击武器造成最大伤害+DB；贯穿武器造成最大伤害+DB，并额外掷一次武器伤害骰。 | **违背** | `resolveAttack` 即使攻击掷出 EXTREME/CRITICAL，仍按正常伤害表达式 `rollDice(...)` 结算，没有取最大、附加 DB 或额外伤害骰；攻击等级只写进日志。 |
| 4.13 | 火器射击：掷 D100 与射击技能比较。 | **原生** | 射击武器被映射到 `FIREARMS_*` 技能，走同一套攻击检定。 |
| 4.14 | 已准备好的火器在决定先攻时视为 +50 DEX。 | **缺失** | 没有“武器已准备”状态，也没有先攻修正字段或调序 UI；KP 只能通过改 DEX（有副作用）或口头说明，系统无法可靠实现。 |
| 4.15 | 同一轮用手枪射击 2 或 3 次时，每次射击各带一枚惩罚骰。 | **不可达** | INITIATIVE 模式每单位每轮只有一次行动，也没有连射/惩罚骰接口；系统内无法表示同一轮多次射击。 |
| 4.16 | 近距离（约 DEX/5 英尺内）开火获得一枚奖励骰。 | **不可达** | 战斗没有距离模型，攻击检定也没有奖励骰注入接口；系统内无法自动判定或执行。 |
| 4.17 | 火器射击的目标不能反击。 | **原生** | `reactionTypesForAttack` 对非 `FIGHTING_*` 的攻击技能移除 COUNTER；火器只留下 PASS/DODGE。 |

## 4. 规则书之外、但会影响入门体验的现有实现

以下内容不是这本《基础规则》的条目，但当前系统默认存在/可选，可能让实际跑团与本书描述不一致：

- **完整版年龄补正**：15–19/40+ 会扣属性、APP、EDU、MOV，并可能出现年龄相关的成长判定；本书创建流程完全没有年龄修正。
- **最大 SAN = 99 − 克苏鲁神话**：完整版 7e 规则，本书只写了起始 SAN=POW；若创建时误加克苏鲁神话，起始 SAN 会低于 POW。
- **ATB 战斗模式**：COC7 房间可被房主改为 ATB，从而不按 DEX 降序行动；本书默认是 DEX 顺序制。
- **DP（骰池）**：东方扩展概念，COC7 基线也会生成 maxDp，与本书无关。
- **极限伤害之外的大成功/大失败分级**：系统会算出 CRITICAL/FUMBLE，但战斗伤害没有极限/贯穿处理，且 `FUMBLE_CONSEQUENCE` 未启用。
- **魔法/符卡/召唤/追逐/战术棋盘**：均为系统增强，不在本书基础规则范围内；用户明确要求不计入东方扩展。

## 6. 结论摘要

- 战斗伤害与应对是违背最集中的区域：闪避比较、反击伤害、极限伤害、火器掩体、霰弹枪距离档、MP 不足扣 HP 均与本书不符。
- 车卡与规则书差异最大：本书是固定数组/固定技能制的入门简化流程，系统是完整版职业点池+上限+职业空位模型；书中的记者示例（CR 40）在系统内甚至会被拒绝。
- 理智/疯狂几乎完全依赖 KP 手工：没有 SAN 检定、SAN 损失模板、临时疯狂、疯狂发作表、恐惧症状态与计时；基线规则包内没有任何 SAN→INSANITY 触发路径（只有自定义法术状态 key 可能写入一个空壳 INSANITY）。
- 治疗/环境伤害/医疗时限/自然恢复依赖 KP 手动改 HP；系统只原生支持“重伤→濒死→每轮 CON→死亡/昏迷”这条核心死亡管线。
- 远程/射击特殊规则受“无距离模型、每轮一次行动、无奖励/惩罚骰注入”限制，属于不可达；不是简单补数据能解决。
